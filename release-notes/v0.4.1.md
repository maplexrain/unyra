归一 Guiyi v0.4.1 —— 一次「把卡顿找出来」的版本：启动更快、切页签不再重建正文、阅读记录每秒落盘并且顶栏的数字实时在走。改动全部由实测驱动，读数都留在仓库的单元用例里。

## 提速

- **启动**（从双击到窗口出现，本机热缓存）：中位 **506 ms → 430 ms**。这一版顺手加了启动耗时追踪
  （`npm run start:trace`），能一眼看到时间花在 Electron 引导、主进程求值、开窗、脚本求值、
  React 首次提交、还是首次绘制上。这次据此砍掉三处白干的活：图标染色的出图尺寸从 256² 降到 64²
  （任务栏只要 16/32）、托盘改到开窗之后再建、消息定位条的锚点只在真的会显示时才量。
- **切页签**：不再重建正文 DOM。解析本来就有缓存（切走再切回 0.00 ms），贵的是把 markdown 产出的
  几千个元素重新塞进页面、四类挂载各扫一遍、几处强制排版。现在最近用过的 4 片教学文档页签常驻，
  切走只隐藏（不参与排版与绘制），切回来直接显示；隐藏的那几片也不会跟着界面刷新白白重渲染。
- **首次安装/更新后的第一次启动会慢一次**（实测约 12 秒）：那是 Windows Defender 在扫 246 MB 的
  可执行文件，与应用自身无关，第二次起就是上面的数字。

## 有效阅读：更快、更实时

- **每秒落盘**：原来进程被强杀（任务管理器结束、断电、崩溃）会丢掉最后那一段还没结算的读数，
  最多 30 秒。现在每秒写一条几百字节的旁路记录，下次启动自动折回来，丢失窗口缩到 1 秒以内。
- **顶栏的数字实时在走**：以前它只在切文档、切页签这类动作把数据刷出来时才跳一下（阅读记录是
  静默写入的，不触发界面重渲染）。现在改成 **mm:ss 每秒递增**，鼠标悬停里的大字也一样。
- **打卡的「还差多久」实时倒计时**：不再只有「还差 12 分钟」这种一分钟粒度的说法，最后一分钟精确到秒；
  点打卡前会先把当前这一段结算掉，不会再出现「顶栏说读够了、点下去说还差 20 秒」。

## 一并修掉的

- 页签常驻带来的一个回归：切走的正文不再卸载，「切页签补一次结算」因此失效——现在停表那一刻就结算。
- 隐藏页签里的函数图像不再按 0 宽度重画一遍（会白跑一次采样，还可能闪一下错误态）。
- 查找、滚动定位、界面操作、导出抓图都收口到「当前显示着的那一片文档」，不会命中常驻在后台的其它文档。

## 说明

- 升级不会碰任何学习数据，也不需要重新激活。
- 安装包没有代码签名，Windows 可能提示「未知发布者」，点「更多信息 → 仍要运行」即可。
