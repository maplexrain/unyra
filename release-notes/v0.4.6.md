归一 Unyra v0.4.6 —— 文档区能分割、右侧栏能收起（Ctrl+Q）；导师有了人格；侧栏接过文档管理；界面上一批打磨（拖页签、定位棱形、编辑模式）；内部做了一次大规模模块化重构。

## 文档区：分割、收起、页签

- **文档区可以分割**：把页签拖到格的边缘，分成左右或上下两格；每格自己一列页签。
  拖动分割线调比例，双击把那一格收掉——最后剩一格时它自己铺满。
- **右侧栏能整格收起**（Ctrl+Q）：收起之后那条分割线也收起来，导师栏让位给正文；
  再按一次展开，光标顺手落进输入框。
- 页签栏现在**只留页签**：文档区右上角悬浮组瘦身成「节点文档 + 源码 / 预览」两件事，
  导出、笔记、超级文档都搬去了左侧资源管理器的右键菜单（见下）。
- **页签右键菜单重排**：一枚图标 + 左对齐的标签，右侧缀上「会关掉几项」的数字。
- **记住读到哪儿了**：切走再切回来，正文回到原来的位置；源码视图与预览各记各的。
- 文档区正文那一列统一成 **850px**（原来是 720），长段落更好读。
- 快捷键：**Ctrl+W 关当前页签**、**Ctrl+Q 收起 / 展开右侧栏**（快捷键改在主进程，**需要重启应用生效**）。

## 导师人格

标题后面括号里那两个字现在可以点：**简洁 / 标准 / ADHD** 三种。

- 人格**不改系统提示词**，而是在下一轮往上下文里补一条指令——所以随手切换不会让历史重发、也不影响前缀缓存。
- ADHD 那套多说人话：多用 emoji 分点、一次只推进一步、少用长段落。

## 左侧资源管理器接手文档管理

- 树里**只显示名字**（不显示描述），每个节点底下直接挂着它自己的**笔记 / 试卷 / 超级文档**。
- **右键节点**：新建笔记 / 新建试卷 / 新建超级文档、学习状态、检验、回忆；
  **右键某一个文件**：在资源管理器中打开、重命名、删除；**右键试卷**：开始考试 / 批改 / 删除。
- 文件图标按类型配色（教学 / 笔记 / 超级文档 / 试卷 / 本地文件各一色），一眼分得清。
- **宽度可调**（200 ~ 400px，默认 280），拖右边那条把手；展开状态只增不减——不会自己收起来。
- 学习状态从「文档顶部的回溯提示」改成**节点标题前的一枚标记**，不再占正文的地方。

## 一批修正

- **复制渲染文档**现在走源文：选中的样式（加粗、列表、链接）会跟着带过去，而不是复制成一段纯文本。
- **笔记不计入有效阅读时长**——写笔记不是读文档。
- **询问引用定位**：同一个词出现多次时，回到你划的那一处，而不是第一次出现的地方。
- 试卷的二级菜单不再被裁掉（悬浮组删掉之后，试卷入口统一在侧栏右键菜单里）。
- 询问输入框在输入到一定长度后不再消失（原因是它自身滚动触发了收起判断）。

## 资源管理器：点行展开，按图标开文档

- **点节点那一行 = 展开 / 收起它的下级**（没有下级时点了不动），
  **行尾那颗文档图标**才是打开这份文档——从前点一下就把正在读的那份顶掉，
  而想看的往往只是「它底下有什么」。
- **试卷行尾多了一颗「考试」**（正在考 / 判分中时置灰）：开考是这一行最常做的事，
  不该只藏在右键菜单里。
- 行上的按钮（打开文档 / 考试）**鼠标经过那一行才现身**——常驻会让整棵树看起来全是按钮。

## 文档区：拖页签、切页签、编辑模式

- **拖页签不再误触分屏**：页签栏就贴在正文上方，从前手往下偏二十像素就会被判成「在上边分割」。
  现在指针要越过栏的下边缘一段距离才认；左右两条边照旧（拖到栏的左 / 右外侧仍然并排分屏）。
- **定位棱形**：页签栏上边框嵌着一颗菱形，停在**当前页签**正上方。
  **按住右键在正文里横划**，棱形跟着指针走，它压到哪个页签就打开哪个——松手回到当前页签正上方。
  从前这件事的反馈是页签底色上的一条进度，看不见「会到哪一个」。
- **编辑模式（源码视图）**：不再显示滚动条；字符间距收紧；字体与预览同一族——
  来回切源码 / 预览时字不再变两次。
- 右上角悬浮组的**源码 / 预览合成一颗按钮**（图标显示现在在哪一边，点一下切到另一边）。
- 输入框左下角那颗「**+**」回到它该在的位置（卡片内左下角）。

## 性能

- **导师逐字回答时界面更跟手**：消息定位条的测量合并到每帧一次（原来每个字都强制整页排版），
  历史消息不再跟着逐字重渲染。
- 拖动分割线、展开 / 收起右栏不再卡（拖动只改 DOM，不触发整棵工作区重渲染）。
- 落盘与读取路径上的几处 O(N²) 修掉：文档树的遍历、整份摊平的序列化、最近打开的排序。

## 内部：模块化重构（行为不变）

一批上千行的文件按职责拆开（>800 行的文件从 16 个降到 1 个），重复实现收成一份，
并拆掉了全部运行时循环依赖（原 25 个模块的大环）。施工图与逐项进度见
`docs/refactor-plan.md`——想改哪一块、为什么这么分，都在那里。

- 拆分为目录 + barrel，**原路径继续转出**，所以既有的引用与插件写法都不受影响。
- 渲染层与主进程共用的 IPC 契约类型收进 `shared/ipc.ts`（以前两侧各写一份，漏改一侧只在运行时炸）。
- 去重经逐条核对，**口径真的不同的不合并**：比如三处 `formatBytes`（1024 / 1024 取整 / 1000。
  更新页那两个数字必须与 GitHub 发布页对得上）。
