# 文档区：页签、分割、源码 / 预览、导出

文档区是整个应用里改动最多的一块。这份文档按「用户看得见的东西」逐条讲它的现状与取舍。
README 里只留了结论，这里是全貌。

## 自由页签（像 vscode）

文档区顶上是页签栏，教学文档、任意一份笔记、任意一个本地文件平级地排在一起。

- 点左侧的知识节点就等于打开它的教学文档页签，页签上**显示节点名**（不再是「教学文档」四个字）；
- **两个页签同名时**，名字前面会多一段淡色的**路径**（节点到目标的路径，本地文件给所在目录）——
  两个节点各有一份「错题本」时，只有路径分得清点哪个；而平时一条路径都不显示；
- 右键页签可以关闭 / 关闭左侧 / 关闭右侧 / 关闭其他 / 全部关闭。这张菜单只有一条排版规矩：
  **一枚图标 + 一个左对齐的标签**，图标对齐在同一列上（方向感交给图标，文字只说人话）——
  ⇤ 收进左边的竖线 = 左边的一起关，⇥ 右边的，⇹ 两枚箭头收向中间 = 左右两侧都关（留下这一项），
  ⊗ 一枚叉装进八角框 = 连这一项一起全都关（最狠的一个，取印章红，与删除同一套语言）；
  每一项右边还有一枚**淡淡的数字**：这一下会关掉几项。
- **关掉某个节点的页签，那个节点就不再是选中样式**——选中态跟着页签走，而不是「上次点过的节点」；
  反过来点开别的节点的那一页，**当前节点与对话一起跟过去**（会话按目标归属，跨目标切页签时
  对话栏不会还停在上一个目标）。
- **改了还没保存的页签，关闭键会变成一颗圆点**（鼠标扫过这一条时才让开，好让你一眼看出哪几份没存）；
  标题在页签里居中、关闭键贴右端。
- 打开的页签与**暂存区**都记在 `state.json` 里：关掉应用再打开，开着的那几份文档还在，
  没保存的改动与那颗圆点也还在。

### 拖动排序

页签**可以直接拖着排序**：页签跟着指针走，其余页签让位，松手即落位并记进 `state.json`；
页签宽度有下限，两个字的标题也按得着；溢出时**激活的那一个会滚到栏的中间**。

松手那一帧只有被拖的那一项从手指底下滑进新位置，让过位的页签**不补间**——
它们的落点本来就等于让位后看到的位置，补了反而会先往回跳一格。

### 右键横划换页签

**按住右键在文档区横向拖动**，每过一个 60px 的阈值就切换一个页签、到头循环。左键在正文里已经有活干
（选字、点链接、划注解），右键本来在正文上没什么可给的，正好拿来当手势的起手式。

拖动时**当前页签的背景里有一条进度**：往右划从**左边缘**长出来、往左划从**右边缘**长出来
（宽度带 100ms 过渡，跟着指针连续长而不是一格一格跳），满一格就换到那一侧的页签。

切页签时新内容会从切换方向轻轻滑进来（anime.js 做，起步值在**绘制之前**写好，不会先闪一下最终态；
尊重「减少动效」偏好）。

## 文档区可以分割

把页签**拖到另一格的页签栏上**就是把它加入那一格（落在哪两个页签之间就插在哪儿），
**拖到另一格的内容区**则是排到那一格的末尾。

**拖到某一格的边上**（上下左右四边各占三成，中间四成见方是「放进这一格」）就在那一侧**拆出新的一格**——
左右贴边 = 并排，上下贴边 = 叠放，想怎么分就怎么分（拆出来的一格还能再拆下去）。
拖动时指针所在的那半边会亮出一块落点提示，松手才真的变。

- **每一格都有自己的页签栏**、自己显示的文档、自己那份源码 / 预览 / 导出；
- 分割线可以拖着调两边的比例（只影响相邻那两格，比例是**占总长的比例**，
  所以缩放窗口之后那条线还在原来的相对位置上）；
- 页签拖走之后原格空了就自动收掉，兄弟那一格铺满；只剩一格时它留着（空态还得有地方放）；
- **拖走的正好是原格当前看的那一份时，原格会自己接上邻居**（先往右找、再往左，与关页签同一条落点规则）
  ——不然那一格会显示「没有打开的文档」，而它的页签栏里明明还有别的页签；
- 空格子在任何路径上都构造不出来：每一个操作的最后都会把空掉的格子收掉（见 `groups` 的 `settle`）；
- 整棵布局与每一格的页签都记在 `state.json` 里，下次打开还是那个样子。

「当前在看哪份文档」由**焦点格**决定：点哪一格，`Ctrl+S`、`Ctrl+E`、大纲跳转、以及导师那套 `ui.*`
（滚动、定位、截图）就作用在那一格上。

## 右侧栏可以收起

两列中间那条线上骑着一颗小按钮（一半在主区域、一半在右侧栏里），点一下把**右边那一格**收起——
宽度补间到 0、内容滑出去，主区域立刻变宽；再点一下回来。

收的是「位置」不是「哪一栏」：默认右边是文档栏，双击分割线对调之后右边是对话栏，
那颗按钮管的仍然是右边那一格（对调时会自动展开，免得刚换过去的对话被收在屏幕外面）。
收起状态记在用户设置里，下次打开还收着。

补间的那 300ms 里那一格裁掉溢出，平时不裁——文档区的 tip、对话栏的模型选择器都要能伸出格子外。
那颗按钮**按整个窗口居中**（比它所在的那一列高半个顶栏，所以向上抬了 28px），高 40px——
它骑在分割线上，是这条线上最常按的东西。

**导师开始干活时右侧栏会自动弹出来**（仅当它就在右侧、且此刻收着）：收着的那一栏等于不存在，
而「它正在写」「它正在判卷」正是这一刻要看的东西；只在开始的**上升沿**做，跑到一半你手动收起来
（想安静看文档）不会再被顶开。

## 两栏可以换边

默认「导师在左、文档在右」，**双击两栏中间那条分隔线**换个位置（走 View Transitions，
两列滑过去而不是唰地换掉；划过那条线不再有高亮，光标形状说明它能拖能双击）。

**拖那条线的跟手感**是三件事凑出来的：

1. 拖动期间**一次都不重渲染**（宽度直接写 CSS 变量，两个读数也直接写 DOM——每帧 setState
   会把整棵学习区重画一遍）；
2. 拖动期间**关掉两格的宽度过渡**（过渡会让它们慢半拍地追指针）；
3. **收起 / 展开的那 300ms 里把主位那一格的正文定宽冻住**（不冻的话每一帧都要给整篇正文重排行盒，
   「展开时卡一下」就是从这儿来的；对面那一格一直这么做）。

**宽度跟着格子走、不跟着内容走**——左格始终自适应，右格始终是拉出来那个宽度，于是换完之后导师栏
落进右边那条窄栏、文档占左边那一大块。这是一个「换位置」的开关，不是「换布局」。

右栏宽度拖着那条线改（400~800px，默认 600，记在用户设置里，见 `lib/appearance`）；
**拖的时候分隔线两边各浮一个宽度读数**（左格 = 行宽 − 右格，右格就是存下来的那个数），
跟着指针上下走、松手就散——分配比例这件事，光看线挪了多少是猜不出两栏各多宽的；
窄屏下两栏自动上下叠放，「对调」在那时就是「谁在上面」。

## 正文那一列只有一个宽度

文档区里读书的那一列固定 **850px** 居中——预览、源码、本地 markdown 文件、试卷副本都收在同一列里
（从前预览 720、本地文件 760、源码干脆铺满整格，切一下视图字就横着跳一下）。

只管列宽：左右内边距各视图自便（源码的 pl-32 / pr-22 与预览那一列的正文左右对齐）；
窄于 850 的格子（分割之后）照旧自适应，列不会比格子还宽。数字只写一处：`index.css` 的 `.doc-measure`；
本地 html 与超级文档不在此列——那两份是网页，按自己的版心排。

## 源码 / 预览

文档区右上角悬浮组**右端那一组按钮**（源码 / 预览 / 导出）——原先它们挤在页签栏右侧，
搬走之后页签栏只回答「开着哪些文档」这一件事，读起来干净得多；它们与那颗悬浮组本来就是一类东西：
**对眼前这份文档做的事**（左边那几颗是「对这个节点做的事」，中间用一道细线分开）。

- **笔记还是空的时默认开在编辑（源码）视图、预览按钮置灰**（空笔记的预览就是一片空白，
  而打开它就是要往里写）：这一笔会写进页签，所以敲下第一个字之后不会突然跳回预览；
- 编辑视图的首行留了一条上边距——画面窄的时候，右上角那排按钮正压在那儿；
- **源码视图里文档可以直接编辑**——改动先进**暂存区**（底栏显示字数与「已保存 / 未保存」，
  页签上是那颗圆点），按 `Ctrl+S` 才写进文档：教学文档与笔记进学习数据、本地文件写回原文件，
  然后立刻落盘。暂存区跟着 `state.json` 一起自动落盘，所以「没保存」丢的只是那一个动作、不是内容；
  把正文改回原样，那条暂存会自己消失；
- **预览只支持 markdown 与 html**，可预览的文件默认就是预览视图，其余（txt 之类）落到源码——
  给纯文本渲染一个「预览」是骗人的。html 用 sandbox 空白的 iframe 渲染：
  本地 html 的样式与脚本不该污染宿主界面。

### 文档区右上角的悬浮组

只留**这份文档**的一件事——**源码 / 预览**（外加一颗「节点文档」：当前页签是从教学文档岔出去的时候
才出现）。

**导出也搬到了资源管理器的右键菜单里**（节点导出教学文档，笔记 / 超级文档 / 本地文件各导出自己）：
导出天生是「对着某一份东西」的动作，而侧栏本来就摆着全部文档；`Ctrl+E` 仍是同一件事的快捷键。

原先它是一条**工具条**，工具条就该待在角落：竖着挂在右边缘时，正文的每一行都要绕着它走。
它**没有外壳**——没有边框、没有底色，几颗图标直接浮在正文上，底色只留给「悬停」时说。

从前这里还挂着**笔记 / 超级文档 / 学习状态 / 试卷**四颗按钮，各自向下展开一块 tip；
**它们都删掉了**：那四样东西现在归**左侧资源管理器**管——一个节点底下直接挂着它的笔记、试卷
（还能展开历次考试）与超级文档，右键给出改名 / 删除 / 在资源管理器中打开 / 开考 / 让导师判分，
以及**学习状态**。动作长在它作用的那一类东西旁边，比挤在正文右上角一列图标里好找得多。

**查找条（Ctrl+F）**本来就排在它下面（`top-14`），两者不叠在一起。

## 大纲栏是一片浮起来的卡片

正文左侧的「本页标题」不再贴着边缘、也不再铺满整列：

- **收起时完全不占布局**（只留一条 40×40 的窄条——**刚好是一颗展开按钮的尺寸**，
  鼠标经过即展开成 250px 宽的卡片）；
- 上下边距 16px（比左边距 8px 大——左右是「贴着正文」，上下是「浮在内容里」）；
- **高度跟着内容走**——三五个标题就是一片矮卡片，几十个标题封顶在「父容器高 − 上下边距」、
  列表自己滚；
- 展开时左 / 上 / 下留白一样宽（8px）、右边不留额外间距，所以它像「一片」而不是「一栏」；
- 固定（图钉）之后才把宽度让出来给正文。此时**点卡片任意非按钮处即可展开**，
  在文档区按 **Tab** 也能收起 / 展开（焦点在输入框里时不抢 Tab）。

## 读到哪儿了会被记住

文档区滚到哪，`state.json` 里就记到哪（键 = 页签 id，见 `lib/docScroll`）——重开应用、
或者关掉页签再打开，回到的是原来那一段，而不是从头再来。

预览与源码各记一份（编辑位置与阅读位置是两回事）；上报走 `patchQuiet`，
滚动时不会为它重渲染整棵学习区。

## 把文件拖进来看

txt / markdown / html 直接拖到窗口任意位置就会被收下并开成页签，内容**不复制**进数据目录——
它仍住在原处，**按 Ctrl+S 才写回原文件**（改动先进暂存区；忘了按也不会丢，只是没落到那个文件上）。
也可以从侧栏右上角用系统对话框挑文件。拖进来过的文件记在「本地文件」里，下次一点就开。

## 查找与替换

`Ctrl+F` 在正文右上角浮出查找条，命中处标出来、回车在命中之间跳；
**源码视图下按 `Ctrl+H`（或点那颗替换按钮）展开替换行**，可以逐个替换、也能一次全部替换。

两种视图两套机制：预览是渲染好的 DOM，命中用 **CSS Custom Highlight API** 给 Range 上色——
**一个 DOM 节点都不改**（插 `<mark>` 会打乱渲染期的注解与 React 的协调，下次重渲染还会被抹掉）；
源码是一个 textarea，命中位置靠扫字符串算，当前那条用选区选中（textarea 内部画不了高亮，
所以那里只报数、不描边）。替换只在源码视图可用：预览是只读的，改源文才有撤销的余地。

## 导出文档

`Ctrl+E`，或资源管理器右键菜单，把当前这份文档带走，三种格式：

| 格式 | 是什么 |
| --- | --- |
| **Markdown 源文件** | 原样，一个字都不加工，适合再导入回来或放进 Git |
| **HTML 网页** | 单文件：排版、公式、图片全部内嵌，双击就能用浏览器打开、也能直接发给别人 |
| **PDF** | 按纸张分页，A4/A3/Letter、横向、页脚页码可选 |

后两种与预览走**同一套解析**（`lib/exportDoc`），渲染期才做得成的那几件事一并补上：

- **注解**：导出件里是虚线下划线 + 悬停看内容；
- **`moji:static` 资源图片**：读成 data URL 内嵌，读不到就在原位留一句说明；
- **函数图像**：把预览里画好的那张 SVG 快照搬过去——导出件里不带绘图库；
- **`moji:` 内部链接**：去掉 href 只留文字，它们指向应用里的东西、在导出件里点不开。

**公式走浏览器原生的 MathML**：KaTeX 的排版靠它自己那二十多个字体文件，想让一份 HTML 脱离应用
还显示正确就得带上两兆字体；而 KaTeX 本来就同时产出 MathML，导出件里隐掉 `.katex-html`、
放出 `.katex-mathml`，零字体依赖、体积不变。

PDF 在主进程的**隐藏窗口**里排版（`printToPDF`）：HTML 先落临时文件再 `loadFile`
（内嵌图片的导出件会超过 data: URL 的两兆上限），用一个独立的内存 session（不受应用那份 CSP 约束），
窗口不跑脚本（导出件里本来就没有脚本）。
