# 有效阅读、注意力与打卡（学习计划的地基）

> 这一层回答「他到底读没读、读了多久、读进去没有」——学习计划、番茄钟与打卡都建立在它上面。
> 采集器的数据形状与落盘细节另见 [reading-mechanism.md](reading-mechanism.md)。

## 按学习目标分开算

一个人同时学几门课是常态：把两门课的时长混在一条曲线上，「今天读了两小时」既不是这门课的、
也不是那门课的，连续天数更是无从谈起。所以阅读账（`store.reading.byGoal`）与打卡账
（`store.checkin.byGoal`）都是**目标 id → 那一本账**，各自落在自己的目标目录里
（`{目标}/reading.json`、`{目标}/checkin.json`，与 `method.json` 同一条纪律）：
删掉一个目标，它的记录跟着一起走，不会在别人账上留一段无主的时长。节点本来就属于某个目标，
所以会话与每节点的记录**天生**可归属——用户级的只是那些按天的汇总。

顶栏那两个入口跟着这个口径走：「有效阅读」的面板左侧是过滤栏（**全部 + 各个目标**），
右侧是这一档的按节点统计与最近一周总时长；「打卡」的 tip 是一份**目标列表**，
每个目标写清还差几分钟，读满的那一行直接变成打卡按钮。

## 只记事实，判断另算

`store.reading` 里存的是会话、区间、分钟桶、中断与交互印记；
档位与结论全是纯函数派生（`learn/attention`、`learn/checkin`），公式改了不用动数据。

| 记什么 | 怎么算 | 为什么 |
| --- | --- | --- |
| 有效时长 | 只有「窗口在前台 + 页签在主位 + 没静坐超过 60 秒 + AI 不在写这份文档 + **看的是教学文档而不是笔记**」的时间才计入 | 文档开着不等于在读；笔记是动手写的地方，在笔记里改半小时被算成阅读，这张账就灌水了（不记账的文档连采集器都不建，见 `learn/useReadingTracker` 的 count） |
| 读到哪一节 | 按**标题**锚定，记每一节进入过视口的最大比例（reach ≥ 0.6 算读到） | 文档是 agent 反复改写的，行号第二天就失效；标题被改写时按「去编号 → 同层最近位置」认领并标 fuzzy |
| 中断 | 只记失焦 / 最小化 / 切走 / 切页签 | 静默（idle）只是停表，另记成 stalls——停在一条公式上很可能是在想 |
| 交互印记 | 展开折叠块、选中词条走「了解 / 注解 / 询问 / 学习」 | 比时长可靠得多的「真的读了」证据 |
| 学习日 | 凌晨 4 点前算前一天 | 23:40 学的那半小时不该被劈成两天，打卡的连续天数全靠它 |

## 四层节奏

**1 秒心跳**（内存里累加，不碰 store）→ **30 秒结算**（走 `patchQuiet` 写盘，
不触发重渲染）→ **离开即结算**（切文档、切节点、关窗前各补一次）。明细有界（全局 400 场 /
每节点 40 场 / 90 天），汇总单调累加——所以那些 reading.json 不会随使用无限长大
（它们按目标分开之后，上限也是**每个目标**各一份）。

文档区最底下有一条 **2px 的进度条**（`components/learn/ReadingPulse`）：一分钟一格、一格一种颜色，
新的一分钟从左边长出来盖掉上一格，十格一轮回——它只说「这一场读进去多久了」，停表时暗下去但停住
（数据源是 `lib/readingPulse` 的脉搏，只有这一条跟着每秒重渲染）。

## 注意力评级

把最近 14 天的会话折成五个维度（每 10 分钟被打断几次、最长连续段、字/秒、
交互密度、前后半场的活跃衰减），给一个档位（专注 / 正常 / 断续 / 心不在焉；样本不足时是
`unknown` + `confidence: low`）、一句事实话、一句教学建议，以及 **focusMinutes**（建议的专注块长度）。
它是**「怎么教」的输入，不是「算不算学」的判据**：掌握度与打卡都不看它。

## 打卡

**每个学习目标一天 3 次机会、一条连续天数、一道 15 分钟门槛**，
题目只能出自**今天在这个目标下真正读到的节**（`api.checkin.status` 的 sources），
用 `api.ask` 出选择题（不占考试窗口），导师自己判分后 `api.checkin.settle` 记结果；门槛与次数由
`learn/checkin` 复核（低于 60% 一律不算过）。这条设计同时堵住两个作弊方向：刷时长的人答不出题，
想纯签到的人没有题可出。连续天数从学习日账本派生，每个目标各数各的；日历（画的是当前目标那一本）
与目标列表都在顶栏「打卡」那颗的悬浮 tip 里。

## 番茄钟

一个**纯计时器**。用户自己设两个数——一段专注多长（10~90 分钟，默认 25）、做几组（1~6，默认 3）；
休息不必设，它固定是专注的 1/5（25 → 5 分钟）。四条定死的规则：

- **只能停、不能暂停**（停下来这一段就作废，要接着跑只能重新开始，而重新开始会重新算）；
- **只有跑完的专注段才记一笔**（休息与半途停掉的不算）；
- **切屏照走**（它记的是「按下了一个计时器」，不是「你真的在学」——后者是有效阅读的事）；
- **agent 只能读**（`api.pomodoro.status`），开始、停止、改时长全在用户顶栏那颗按钮上。

倒计时只存每一段的**起点**，剩余时间由 now 现算，所以关掉应用再打开计时接着走；到点由每秒的钟收尾
（`tickPomodoro`）并弹一条提示——关得太久（超过 `LATE_GRACE_MS`）就整次作废，绝不写没发生过的时长。

## 读网页（`api.web.webFetch`）

抓一页并转成 markdown。抓取在**主进程**（渲染层的 fetch 受同源控制，抓任意站点一律被 CORS 挡下），
正文提取与 markdown 化在**渲染层**（`lib/web/dom` 要 DOMParser，`lib/web/page` 是纯函数）。
两万多字以内直接把全文回给模型；再长就**存成文件**
（`users/{uid}/web/{uuid}.md` 是正文、同名 `.json` 存来源与大纲），只回一棵大纲树——每行是
「`# 标题 - 这一节正文的字数`」（不含子节），模型据此用 `api.web.read(uuid, '一级标题/二级标题')`
按节读（一次最多回 1.2 万字，没回完会在回执里说怎么继续）。三条硬规则写在 `electron/web-core.ts`
里、用例钉着：只读（不带 cookie 与本机凭据）、有上限（4MB / 20 秒）、**本机与内网地址一律拒绝**
——agent 是模型写的代码，不能给它一个读本机服务的口子。

## 顶栏那几颗入口

`components/learn/CheckinButton`、`PomodoroButton`、`ReadingButton` 是纯展示组件：
数据与回调由 `LearnWorkspace` 算好传进去，悬停展开的时序与 `UserMenu` 同一套；它们各自订阅 `lib/clock`
的秒针快照（`useClock(1000)`），所以只有这一小块跟着时间重渲染。
