# 学习状态：掌握度、错题与回忆

> 一个知识点不再只有「学习中 / 已掌握」两种状态。它还带一份**学习状态**
> （`node.learning`，落在该节点 `.meta.json` 的 `learning` 字段里）。

| 组成 | 回答的问题 | 谁写 |
| --- | --- | --- |
| 自评（四档） | 他自己觉得会不会 | 学习者点选；导师也能先替他猜一个，标成「未确认」 |
| 掌握度 0~100 | 系统估计他掌握到什么程度 | 导师，依据探针 / 考试 / 回忆 / 错题 |
| 错误记忆 | 他**错成了什么样**、犯过几次 | 导师；同一个说法再犯只累加次数 |
| 检验记录 | 最近几次探针 / 考试 / 回忆的结果 | 考试由程序在阅卷完成时自动记；探针与回忆由导师记 |

自评四档是**掌握 / 了解但不熟 / 不会 / 不确定**。

## 几个刻意的取舍

- **自评与掌握度是两件事，各存各的**。自评是学习者的主观判断（`self` 加一个 `selfBy` 说明
  是导师猜的还是他确认的），掌握度是系统的估计。「他说他会」不会让掌握度自己涨——
  那恰恰是要用探针去戳的地方；反过来说，自评与实测差得远本身就是最值钱的一条信息。
- **掌握度是估计值，允许来回走，但每次都得带上依据**。导师改它时必须写一句 `note`，
  面板上就显示在那根进度条下面。一个不能被追问的数字，很快就会没人看。
- **错误记的是「错成了什么样」，不是「第 3 题错了」**。同一个说法再犯只把次数加上去，
  于是「漏乘内部导数 ×3」这种反复出现的模式会自己浮出来，下一次讲解可以正面处理它，
  而不是把同样的内容再讲一遍。
- **没评估过就是没有**：`mastery` 是 `null`、界面显示「未评估」，不用 0 分冒充「测过了，0 分」。
- **知识深度不是学习者的水平**。`api.state.read()` 里的 `depth` 是这个知识点在依赖树里
  离学习目标有多远，只说明它建立在几层前置之上；它只作为结构信息展示，不参与任何
  「深度大 = 基础差」的推断。基础看的是掌握度、自评与错误记忆。

## 界面在哪

在**资源管理器的节点右键菜单**里：「学习状态」那一项鼠标停上去向右展开一块面板
（自评四档、掌握度与依据、知识结构、错误记忆、检验时间线）。

面板分**两栏**——左「现在什么水平」：掌握度与依据、自评四档；右「一路上的痕迹」：
错误记忆、检验记录。两个动作与结构那一行分别占标题栏与页脚；竖着摞成五块的话，
一块 tip 会长到要滚三屏。它**没有遮罩**，也不占布局（文档列宽度一点不变）。

tip 里也能直接发起两个动作：

- **回忆一下**：合上文档、用自己的话讲一遍，导师给出「讲到了 / 漏了 / 说错了」三样，
  把说错的地方当场纠正并记进错误记忆；
- **探个针**：一两个不用计算就能回答的短问题，专门验证自评。要出一整张卷那是「试卷」的事，
  两者不混。

节点标题前那颗**小点就是学习状态**（未掌握 / 已掌握，配色见 `mastery` 的 `STATUS_META`）。
从前它是文档区顶上那句「前置已就绪，可以回溯」提示条的一部分，那句话删掉了：
状态是要一眼扫过整棵树看出来的东西，不是每开一份文档就弹一次。

## 导师侧怎么用它

靠四件事把它用起来：

1. 新增节点后先 `api.state.read()` 看一眼——有错题就正面处理那个错法；
2. 前置知识里判断不准的**最多挑 3 个**问一句「我觉得你可能……，对吗」；
3. 自评只当线索，掌握度要有证据才动；
4. 发现的错法立刻 `api.state.mistake` 记下来；知识深度不当作「他基础差」。

> **这一版还没做**：间隔复习的排程、日 / 周学习报告的呈现、最小学习单元、知识迁移的横向关联；
> 番茄钟、打卡与注意力评级已经落地（见 [reading-and-checkin.md](reading-and-checkin.md)），
> 它们缺的不是代码量而是一个判据——比如「多长时间没动静才算走神」「掌握到什么程度算过关」——
> 定下来再做才不至于做成一个没人信的数字。掌握度本身现在也只存不用：它还没有参与
> 「要不要进入下一个节点」这类自动决策，那属于动态学习路径，同样待定。
