# 超级导师

> Agent 本身怎么跑：人格、上下文压缩、工具气泡、它自己那一小片设置，以及用户画像怎么被取用。
> 它能调什么见 [sandbox-api.md](sandbox-api.md)，对话怎么组织见 [learning.md](learning.md)。

## 一个目标一份上下文

目标下所有节点共用同一段对话，切节点不换上下文，系统提示词也稳定在目标一级
（前缀缓存因此不会因为切节点而整段作废）。Agent 先思考、再写一段 JS 交给沙箱执行：
文档读写、节点增删改、描述、试卷、临时变量全在这段代码里编排，讲解**直接写进教学文档**，
并在对话里说明改动理由。

## 导师人格

导师栏左上角的标题后面括号里的那两个字就是当前人格（「超级导师（标准）」），
**鼠标经过向下展开三种**：

| 人格 | 性格 |
| --- | --- |
| **简洁导师** | 冷静的解题者，直奔主题、只解释「为什么」 |
| **标准导师** | 耐心的讲解者，**默认**，先直觉再原理、会停下来等你想一步 |
| **ADHD 导师** | 停不下来的好奇鬼，主线 + 支线，允许跑题但必须跑回来，**而且多用 emoji**：emoji 是它的语气而不是装饰，跟在关键词后面当视觉锚点，一段话两到四个 |

每一行带一句它自己的口头禅，点一下即切换。

**人格不进系统提示词**，而是切到的那一刻往上下文里补一条**隐藏的 user 消息**
（与工作流同一种东西：界面上是一条「导师人格 · XX」的分界条，正文只在上下文里）。
这么做的两个理由写在 `agent/persona` 开头：换人格**不重发历史、不作废前缀缓存**
（系统提示词是上下文最前面那一段，人格写进去的话每次切换都从第一个 token 起全部重算），
而人格恰恰是「一边聊一边换」的东西。一段对话里同一个人格只补一次；
那条被压缩掉之后会自动补回来（长对话聊到一半不会悄悄变回默认语气）。

三种人格共用一份**共同底线**（以理解为第一目标、不牺牲准确性、不装懂、不重复讲已掌握的、
按实际水平调整、主动补前置、人格只改表达不改结论），那段底线也逐条写在注入的指令里。

## 上下文压缩

聊久了，上下文里堆的主要不是「讲了什么」而是过程的残渣（每次工具回填的 JSON、读过的整篇文档、
几轮之前的逐字草稿）。压缩**是一个工作流**：导师自己写一份**交接摘要**
（学习目标与背景 / 已讲清的结论 / 学习者的状态 / 约定与术语），再调 `api.compact({ summary, tasks })`
落进会话；**本轮结束之后**它才生效——那之前的消息**全部失活**（`retired`），一条原消息都不再进上下文，
此后只有摘要（排在消息最前面，系统提示词仍在它之前）+ 之后的新消息。

**还没做完的事单独放在 `tasks` 里**：逐条写、拼进上下文时排在正文之前——压缩最容易丢的
就是「上次做到一半的那件事」。触发有两种：菜单里手动点（跑「压缩上下文」工作流），
或者**上下文用到 70%（可调）时自动压**一轮（判据是服务端上一轮报回来的真实用量，不是估算）。
阈值与自动开关在「更多 → 超级导师设置」那个弹窗里改（见下）。界面上那条虚线是**失活的分界线**，
点「看摘要」能核对导师到底记住了什么。

## 工具气泡按工具说话

`execute` 那一步展开后显示的是它写的那段 **JS 源码**（排好版、按 JavaScript 语法上色），
而不是 `{"description":…,"body":…}` 这坨参数 JSON——说明已经在标题上了，正文里再摆一遍
就是同一句话说两遍。结果同样排版 + 高亮（是 JSON 就缩进上色），其中**关于这次调用本身的话**
（调了哪些 api、日志、哪几次没生效）摘出来渲染成注释（`// …`，颜色取自代码主题的注释色）：
它们是旁白而不是返回值，与数据混在一段里读的人分不清哪句是哪句。参数还在流式长出来的时候
也读得出正文（JSON 解析失败就退回宽松抠字段），所以展开着看它写代码是能一段段长出来的。

## 思考可见与跟随

- **思考可见**：思考气泡收起时露一行「最后一行」，不换行、持续往右滚——模型安静十几秒时
  也能一眼看出它还在写，而不是卡死。
- **跟随与脱离**：输出时对话列表自动贴底；在列表里往上滚一下就脱离跟随（右下角浮出「回到最新」按钮），
  读上面的内容不会被反复拽回底部，滚回底部或点那颗按钮即恢复。
- **消息定位条**：导师栏右边那排小点是**消息定位条**——一个锚点一个点，**从上到下就是第一条到最后一条**。
  锚点不只是「我发过的话」：导师**自己发起**的那些动作（回忆 / 探针 / 出卷 / 阅卷 / 开讲）在对话流里
  画成一条细小的分界条（隐藏指令照旧不显示正文，只标出「这里发生了什么」），它们同样是锚点——
  否则「导师带我做的那次回忆」在长对话里根本找不回来。鼠标停上去先看一眼预览（70 字，带图的标一下），
  点一下直接跳到那一条；**滚动停稳之后**那条消息才闪（描边 + 轻微放大，1.1 秒——滚动那几百毫秒里
  人还在追着屏幕看，那时候闪等于白闪）；现在读到哪一条，那个点会变粗变红。

  点与点**等距排、间距 22px**；消息多到一屏放不下时按整条轨等分。不按它在对话里的位置排——
  那样两条消息会一个贴顶一个贴底，中间空出一大片，反而对不上号。每个点的**命中区就是整个间距、
  上下相接**，所以鼠标顺着那条子上下走不会在两点之间「踩空」（看得见的那道线画在伪元素上、
  只有 3px，点与点之间照旧是分开的；划过时是手型光标）。它挂在**导师栏自己的右边缘、离边 12px**
  （不是消息列的右边缘——消息列有 768px 上限、宽屏时还会居中，挂在那里点会跑到中间去），
  消息列表因此不再画滚动条（`moji-scroll-none`：滚轮、触控板、PageUp/PageDown 照常，
  只是不占右边那条槽）。只在**导师栏宽度 ≥ 600px**（`AgentPanel` 的 `RAIL_MIN_WIDTH`）
  且用户消息不止一条时出现：窄栏里它挤掉的正是消息本身。

- **字号**：对话的字号与文档区一样用 **Ctrl + 滚轮**调（两处各记各的，右下角同样浮一个比例提示），
  都记在用户设置里。

## 输入框左下角的「+」

点一下在输入框**上方**弹出一块与它等宽的菜单（绝对定位、不占位，所以弹出时输入框不会跳）。
一级是 **新建对话** / **对话历史**（二级）/ **文件**（把文件发给导师看，不设扩展名过滤）/
**工作流**（二级）/ **压缩上下文** / **超级导师设置**（开一个只配置 Agent 的弹窗）。

带二级的那两项**换层而不是执行**：面板顶上多一截面包屑（点它退回一级），两层之间**滑着换**——
往里走新的一层自左滑入、旧的一层向右滑出，退回来方向相反，层级关系因此是看得见的
（与输入框右下角那个「提供商 · 模型」选择器同一套做法）。

**工作流**底下是**回忆**（与文档区那颗按钮同一件事，只是这里不二次确认）/ **超级实验室** / **打卡**；
**对话历史**底下是当前目标的那几段对话（标题 + 消息条数，鼠标扫过一条才露出删除键）。
「压缩上下文」仍留在一级：它是随时可能顺手点一下的动作，而上面那三件都是「发起一轮工作流」。

输入框右下角原来那颗「添加图片」的按钮因此删掉了：文件那条入口本来就包含图片，
两颗按钮做同一件事只会让人猜「图片走哪条」。顶栏原来那颗「对话历史」下拉也删掉了——
切换对话搬进了这里，顶栏右上角那个位置留给「这一段叫什么」。

## Agent 设置（与全局设置分开）

超级导师自己有一小片设置，**不在全局设置里**，而是「更多 → 超级导师设置」那个弹窗
（`src/agent/settings.ts` 与 `components/satellite/AgentSettingsPanel.tsx`）。分开是因为
两件事回答的问题不同：

- **全局设置**（顶栏那颗齿轮）回答「用哪家的哪个模型、Key 是什么」——它是描述生成、短释义、
  出题阅卷这些 AI 功能的共同基底，改一次影响一大片；
- **Agent 设置**只回答「这个 Agent 自己怎么跑」：**自动压缩开关**、**压缩阈值**（默认 70%，
  可选 40%~95%）。放进全局设置那张大表里，用户会以为改阈值也会影响阅卷。

三处取舍写在代码里，也值得在这里说一遍：

- **默认 70% 而不是 90%**：一轮里模型要来回好几跳，每一跳的输入都比上一跳大（工具结果要回填），
  压到只剩一成余量时最后一跳很容易顶着窗口报错，而**压缩本身**也要跑一轮工作流。留三成余量够跑完一轮。
- **压就压干净：一条原消息都不留**（曾经「保留最近 N 条」，现在不留了）。摘要由正在讲课的这位导师写——
  它本来就看得到整段上下文，为压缩再发一遍历史是白花的钱；而留着半截原话时，模型会同时看到
  「摘要里说」与「原话里还说」，两边不一致时它信哪个全凭运气。于是压缩 = 全部失活 + 摘要成为第一条消息。
- **摘要会取代原文继续对话，但原文一条都不删**：界面上一目了然（淡显 + 一条分界线），
  点「看摘要」能核对导师到底记住了什么。没做完的事在 `tasks` 里逐条留着——**压缩不许把「做到一半」丢掉**。

## 用户与画像

- **用户级隔离**：学习目标、知识节点、对话记录与模型设置都按用户分命名空间存储，互不可见。
- **用户画像**：昵称、年龄、性别、语言、教育程度、专业背景、当前身份、工作经验、技能。
  **它不再被拼进系统提示词**——画像挂在 `api.userInfo.get()` 上，导师动笔讲、出题、写文档之前
  自己取一次（取不到就按通用深度讲，不许臆断）。这样改有两个原因：用户改一次资料，原先那段系统提示词
  就整段作废、之后每轮全价重算；而绝大多数轮次根本用不到画像里的任何一项。
  - 归档与分界：画像存**他是谁**（跨目标，落在 `user.yaml`），`mind` 存**你们之间定下的事**（按目标）。
  - 补全走表单：`api.ask` 的题目上写 `userInfo: '字段名'`，用户在表单里作答，**提交的那一刻答案
    就直接写进画像**（见 `src/user/fields.ts` 的 `patchFromAnswers`），导师不必再 update 一遍——
    也就没有「模型转述走样」这一步（「本科」被写成「大学本科学历」那种）。写不进去的值会逐条回报，
    不会因为一个字段不合法就整张表单作废。
  - `userInfo.update` 是**增量**语义：只写传进来的字段，其余原样保留。字段名写错、年龄越界、
    性别认不出都会当场说明并列出可写字段；超长文本按存储层的上限截断，并在回执里说明截了。
  - 头像是纯展示的：它是一段 data URL，**永远不进模型上下文**（`profileForModel` 里就摘掉了）。
- **登录**：本地账号（选一个本机用户进入），导航守卫保证未登录只能停在登录页。
