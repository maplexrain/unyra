# 有效阅读（reading）：当前机制

> 这份写的是**现在**跑的这套东西，用来当「优化有效阅读」的讨论底稿——只描述，不提方案。
> 代码位置：`src/learn/reading.ts`（数据与纯函数）、`src/learn/useReadingTracker.ts`（采集器）、
> `src/learn/readingJournal.ts`（崩溃兜底）、`src/learn/attention.ts`（评级）、
> `src/learn/checkin.ts`（打卡）、`src/learn/store.ts`（落盘/读回）、
> `src/components/learn/NodeNote.tsx`（挂载点）、`src/components/learn/LearnWorkspace.tsx`（顶栏读数）。

## 0. 一句话

「有效阅读」= **这份文档真的被人读着**的那段时间。它按会话、分钟、节记下来，
是注意力评级、打卡、以及导师（agent）判断「他学到哪了」的共同事实底座。

三条设计红线（`reading.ts` 文件头，改它之前要先认）：

1. **只记事实，判断另算**。这里存会话、区间、分钟桶、中断、交互印记；档位、分数、
   结论一个字都不许写进来（评级公式一定会改，改公式不该动数据）。
2. **粒度到会话与分钟**。注意力是时间序列不是标量：番茄钟要知道「第几分钟开始散」，
   教学策略要知道「他能连续专注多久」。
3. **按学习日聚合，而且跨节点**。打卡问的是「今天读了什么」，可能横跨好几个节点；
   23:40 学的那半小时也不该被劈到两天。

## 1. 存什么（数据形状）

`state.json` 里的 `reading`（没有磁盘镜像，整块存在这一份里）：

| 字段 | 内容 | 上限 |
|---|---|---|
| `sessions[]` | 一场阅读的明细：`{ id, nodeId, doc, day, from, to, activeMs, minutes[], breaks[], sections[] }` | 共 400 场；每个节点 40 场 |
| `nodes{}` | 节点汇总，键是 nodeId：`{ docs{}, activeMs, firstAt, lastAt, opens }` | 无（每删一个节点就少一条） |
| `days{}` | 学习日索引，键是 `2026-09-20`：`{ day, activeMs, nodes[], marks }` | 最近 90 天 |

- `nodes[id].docs{}` 按**文档**再分一层，键是 `teaching` / `note:笔记名` / `sdoc:文档名`
  （见 `readingDocKey`）。一份文档里存 `sections[]`（每节的累计毫秒、进入过视口的最大比例
  `reach`、交互印记 `marks`、首末时间）、`activeMs`、`words`、`doneAt`。
- `minutes[]` 是**这一场的分钟桶**：第 N 分钟里累计的有效毫秒、滚过的字符数、印记数、
  中断次数。注意力回放与 pace 都读它。
- `breaks[]` 是停表记录：`{ at, ms, kind }`，kind 有
  `blur | hidden | tab | idle | doc | exam | write | away`（`doc` / `exam` 是留给
  「切文档」「考试窗口」的位，目前采集器不产出）。三档判据见 `attention` 的 `REAL_BREAKS`：
  `blur/hidden/tab/doc/exam` = 真的被打断；`idle` = 静默（中性）；`away` = 没在读；
  `write` = 哪一档都不算。
- **锚是「节」而不是行号**：文档是 agent 反复改写的，行号第二天就失效；标题是最稳的东西。
  `sectionKey` 归一化标题（保留编号），认不出时退到 `looseSectionKey`（去编号）、再退到
  「同层级里位置最近」（标 `fuzzy`），三档匹配见 `matchSections`。

## 2. 采集（谁在计时）

采集器 `ReadingTracker` 挂在 `NodeNote` 上（也就是「正在看的这份文档」这一层），
因为判定「有效」要看的东西全在界面这层：滚动容器、窗口焦点、页签主位、agent 是不是正在写。

**计时规则**

- **1 秒一拍**（`BEAT_MS`）：拍里把这一秒记到**占视口面积最大的那一节**头上
  （`attribute`），并累计「这一秒新滚过的字符数」——回看不会把 pace 刷高。
- **要有阅读证据才计时**：最近一次交互发生在**文档区里**（滚动、点正文、按键、选中），
  并且离现在不到 60 秒（`IDLE_MS`）。切回来、在对话栏打字、点侧栏——都算「没有证据」，
  表停着。证据过期记 `idle`（中性事实：多半是在想），「没有证据」记 `away`。
- **打开 / 切到这份文档、把文档切回主位**：给 20 秒宽限（`RESUME_GRACE_MS`）。这三个动作是
  明确的选择，不必先交互；但宽限里一次交互都没有就停——**回来不等于在读**。
  从别的应用切回来（alt-tab、点任务栏、最小化恢复）没有宽限，必须有一次文档区交互。
- **文档不在中间主位**（导师栏占着主位）：那段时间一律不算，窄栏里跟读的时间直接丢。
- 另外三种停表：失焦（`blur`）、最小化/切到别的窗口（`hidden`）、切走页签（`tab`）、
  agent 正在写这份文档（`write`）。
- 这些停表**不是同一种东西**（见 `BreakKind`）：只有「真的离开」（blur / hidden / tab / doc /
  exam）算中断（fragmentation）；`idle` 只记 stalls（中性事实）；`away` 既不中断也不卡住，
  它只把「连续阅读」在那一段切开。这条不守住，用户第一周就学会表演阅读。
- 睡过去了（合盖、进程被挂起，一拍 > 5 秒）那一段直接不算，只把表拨回来。
- **交互印记**（`mark`，6 种）：`details`（展开折叠块）、`learn`（点「了解」）、
  `annotate`（注解）、`ask`（就选段提问）、`select`（选中正文）、`note`（写笔记）。
  它比时长可靠得多，是注意力里的 depth（深度）维度。
- **热身门槛**（`WARMUP_MS` = 20 秒）：今天还没读过的标签页，要**在这一页上真的动过**
  （滚动 / 点击 / 按键 / 选中，且发生在文档区里）**并且**累计够 20 秒才开始写、才开始显示。
  过线那一刻，前面那 20 秒**整段都算**——它是门槛，不是折扣。今天已经读过这份文档的
  （`readToday`：今天的会话里有它，或它的最后读数就在今天）直接算，不再热身。
- **读完判定**（`doneAt`）：每一节都 `reach ≥ 0.85` 且这份文档累计 ≥ 60 秒。
  「读到了」的线是 `SECTION_REACHED = 0.6`（进过视口的比例）。

## 3. 四层节奏（决定了会不会拖慢、崩了丢多少）

| 节奏 | 做什么 | 碰不碰 store |
|---|---|---|
| 1 秒心跳 | 内存里累加、发布给进度条 | 不碰，也不触发渲染 |
| 1 秒旁路 | 把「还没确认落盘的那一段」写进 `reading-tick.json`（几百字节） | 写旁路文件 |
| 30 秒结算 | 攒够一次增量交给上层（`onDelta`） | 走 `patchQuiet`：只改 ref + 排队落盘，**不重渲染** |
| 离开即结算 | 切文档 / 切页签 / 关窗 / 打卡前补一次，最后那一分钟不丢 | 同上 |

结算走的是**增量**（`ReadingDelta`：全是「加上去」的量，`reach` 取 max、`marks` 取并集），
所以重复结算、崩溃重放都不会算两遍。旁路文件是为「进程被强杀 / 断电」准备的：里面的
`live`（从没进过 store 的那一段）一律折回来，`chunks`（交给 store 但可能还没落盘的那几段）
只在比 store 里那场会话的 `to` 还新时才折——折完就删文件（见 `readingJournal`）。

顶栏那两个数字之所以能「每秒往上走」，是因为另有 `lib/readingPulse` 这条订阅通道：
采集器把这一场的读数发布出去，只有那条进度条/那个数字重渲染，正文与对话栏不受影响
（已落盘的取 store 快照、刚结算的取发布值，两者取**较大者**——快照可能落后于刚结算的那一份；
  再加上这一场还没结算的脉搏，见 `ReadingDock`）。

## 4. 谁在读它（消费者）

- **导师（agent）**，四个只读 api（见 `agent/apiCatalog.ts` 的「学习过程」组）：
  - `reading.get(path?)`：这个节点的有效时长、打开次数、各文档读到几节、最近会话；
  - `reading.list()`：当前目标里每个有记录的节点一行，带**未读的节**——「第 3 节还没看」
    就是从这里出来的（`readingIndex` 的 `unread`）；
  - `reading.day(day?)`：某个学习日读了什么（时长、节点、印记）；
  - `attention.get(path?)`：把事实折成档位 + 一句事实 + 一句建议 + 建议的专注块长度。
    **它是派生结果，绝不落盘**，随时能用历史会话重算。
- **打卡**（`checkin`）：门槛是今天 `activeMs ≥ 15 分钟`（`MIN_DAY_MS`），
  题源是今天真正读到过（`reach ≥ 0.6`）的节，至少 2 节才出得了题，一天 3 次机会，
  通过线由导师定但比率不得低于 0.6。
- **界面**：顶栏的阅读入口（今天多久 + 今天的节点清单 + 近七天柱子）、紧挨着的打卡入口、
  文档区**最左边那条 2px 实时进度条**（一分钟一格、从上往下长，停表时暗下去但停住）。
- **番茄钟**：建议时长取自 `attention.get` 的 `focusMinutes`（样本不足给 25 分钟默认值）。
- **学习计划**：目前**没有独立界面**，「哪一节还没读」只有导师通过 `reading.list` 读到。

## 5. 落盘与读回

- 写：`buildState` 把整块 `reading` 塞进 `state.json`；空记录不写这个键。
- 读：`normalizeReading` 逐字段校验（坏数据整块丢，不拖垮整库）→ `compactReading` 收上限
  → `pruneReading` 按**还活着的节点**过滤（见下）。
- 崩溃兜底：启动时折一次 `reading-tick.json`，折完再按存活节点过滤一次。

### 空索引（本次修的那件事）

记录全按 nodeId / 文档名索引，而节点和笔记都是**会被删掉**的。删了之后那些索引就指向
不存在的东西——**空索引**——症状是界面上一行坏数据：今日阅读面板里冒出一行标题是 uuid、
点不动的条目（`ReadingDock` 里 `nodeById(...)?.title ?? nodeId`），agent 的 `reading.list`
也照报一串 uuid，分节点统计里还挂着它。

规矩（用户定的）：**检测到空索引，就连带那条记录一起删掉**。现在有四道口子：

1. 删节点 / 删目标：`graph` 的 `deleteNode` / `deleteGoal` 顺手清掉整条记录（含明细会话、
   学习日索引里的那个 id）；
2. 删笔记 / 删超级文档：`graph.deleteNote` / `superdocs.removeSuperDoc` 清掉那一份文档的记录
   （`note:名字` / `sdoc:名字`）——节点那条记录留着，时长是这个节点的真实经历；
3. 笔记**改名**：记录**搬**到新名字下（`moveDocReading`，与页签、暂存区同一条规矩），
   不是删——名字换了，文档还是同一份；
4. 读盘 + 折旁路文件之后：按存活节点再过滤一次，清掉以前留下的旧空索引，也兜住
   「删节点那一刻采集器正好在结算」这种竞态（那一笔在 `LearnWorkspace` 的 `onReading`
   里被挡掉）。

**学习日的总时长与印记不参与删除**：那是「今天读了多久」的账，时间是真花掉的，
不因为后来删了个节点就缩水（打卡资格也算在它上面）；而且 per-day per-node 的时长
没有单独存过，也没有可靠的减法可做。删的只是「这一天读过哪些节点」里已经不在了的那几项。

## 6. 现存薄弱处（供讨论，都是事实，不是提案）

1. **明细上限会让分节点统计偏小**：`readingSince` 的 per-node 分布走 `sessions`（400 场 / 节点 40 场），
   滚掉之后那部分时长就只留在节点汇总与学习日总账里，两边对不上。
2. **节点的「最近学习」是天粒度**：`withVisit` 同一天内不刷新 `lastStudiedAt`
   （为的是别每点一下都重写 `meta.json`），所以「最近打开」在一天内的排序是
   「这天第一次打开的先后」，不是最后一次。
3. **有效时长只认「在文档区里动过」**：在另一块屏上、纸上、打印稿上读的时间一律为 0；
   安静地盯着同一屏读、久到超过 60 秒静默也会停表（再滚一下才接着算）。这是口径而不是 bug，
   但「有效阅读」这四个字在用户那里的含义可能比这宽。
4. **数字比改之前小**：打字问导师、看导师回复、在窄栏跟读、切回来先看一会儿，过去都算，
   现在都不算。打卡那条 15 分钟门槛（`MIN_DAY_MS`）与注意力里的阈值还没有跟着重标——
   先按新口径跑一段、拿真实读数再定。
5. **reach 是「进过视口」而不是「读进去了」**：长节、图解节可能被低估；
   `paces`（字/秒）只在个人基线下有意义，绝对值目前只用来发现异常。
6. **门槛与阈值全是常量**：20 秒热身、20 秒宽限、60 秒静默、0.6 到达线、0.85 读完线、
   15 分钟打卡门槛、14 天注意力窗口……没有一处可配。
7. **改名的历史不留**：笔记改名会把记录搬到新名字，但 `sessions[].doc` 里留的还是旧名字
   （历史事实不重写）。要按文档回看历史会话时会看到一个已经不存在的名字。
8. **删除是不可逆的**：按上面的规矩，删节点就把它的阅读记录一起删了（用户定的）。
   删掉之后，那一天的总时长还在，但「那段时间花在什么上」永远查不回来了。
9. **没有跨设备 / 导入合并**：阅读记录跟着 `state.json` 走，导入一份别人的备份时
   一律以「我这一份」为准（见 `mergeStores`），两份记录不会合并。
