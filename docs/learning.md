# 探索式学习：目标、节点与大纲

> 从 README 的「核心功能」一节拆出来：**学习是怎么组织的**，以及围绕它的选词菜单、注解、文档跳转。
> 界面本身的排版（页签、分割、侧栏树）见 [workspace.md](workspace.md)。

## 从目标开始

输入一个想掌握的问题，立刻建出根节点与这个目标的上下文；Agent 随后自己给目标起标题、写描述，
并给出一份可点击的系统性学习大纲（不再先等一次「生成描述」的请求，界面当场就有反馈）。

## DAG：节点是独立的知识点

知识点是独立节点、依赖关系是独立边，**同一概念可被多个上层节点引用而不重复创建**；
标题、描述与每一份文档都支持 Markdown 与 LaTeX，并可用 ```` ```plot ```` 围栏画函数图像；
教学文档的**正文以 HTML + Tailwind 工具类为主**（见 [rendering.md](rendering.md) 的「文档里的 Tailwind」）。

节点由 Agent 打理：标题、描述、正文、下级节点的创建与删除都有对应的 api
（见 [sandbox-api.md](sandbox-api.md)），一次编排里可以把好几个节点一起安排明白。

**教学文档是读物，不是待办表**：提示词里明令**不许**在正文写「自查清单 / 打勾清单」这类收尾表
（要交互就做成超级文档）；主栏也由导师主动切换——内容写进文档就切到文档，需要你回答或动手就切回对话。

**正文以 HTML + Tailwind 写**（2026-11 起，此前是「Markdown 为主、HTML 为辅」）：讲义真正要的是分栏、
对照、图表与时间轴，Markdown 表达不了，最后总得内嵌 HTML——两套语法混着写，模型的力气一半花在
「这段能不能用 Markdown」上。渲染器因此自带一份**运行时 Tailwind**（见 [rendering.md](rendering.md)）：
文档里写的工具类现算成样式，颜色走应用自己的主题令牌（`bg-paper` / `text-ink` / `border-line`…），
深浅色主题自动跟随。

Markdown 没有退场：**文件格式仍是 `.md`**——公式、图片、复制源文、按行定位、导出、源码视图全都照旧，
变的只是「正文主体怎么写」。三条尺度上的约定写进了提示词：正文列宽上限 **800px**（可用约 745px）、
两栏按每栏约 350px 排、文档动画只用现成的四个（`animate-doc-fade` / `rise` / `grow` / `draw`）。
更细的配方（提示框、两栏对照、步骤时间轴、条形图、柱状图、折线 SVG 的可抄模板）住在
提示词模块「文档排版与图表」里。让模型**真的用上**它靠三道保障，缺一条都会退回「一篇只有
<h2> 与 <p> 的 HTML 草稿」：

1. **系统提示词点名最常犯的失败**：只写裸标签等于没有排版；给出默认字号表，降低每次重新想层级的成本；
2. **配方在动笔之前就位**：「开讲」与「学习大纲」两条内置工作流带 promptModule: doc-html
   ——靠 doc.* 写入触发只会晚一轮；
3. **回执里有一句排版提醒**（learn/ops/assemble 的 layoutHintOf）：整篇写入教学文档、正文里
   一处 class 都没有时，回执补一句——文档好不好看模型自己看不见，而回执每轮都在眼前。
   只认教学文档、只认整篇写入、太短的不算（三条都是「别唠叨」）。

## 选词建节点

在文档里选中陌生概念，弹出菜单：

| 项 | 数字键 | 做什么 |
| --- | --- | --- |
| 学习 | `1` | 在当前节点之下创建子节点并自动开讲 |
| 了解 | `2` | 让导师在正文上划一条两三句的注解 |
| 注解 | `3` | 写下自己的 Markdown 批注（可改可删、可设文字样式） |
| 询问 | `4` | 就选段向 AI 提问，并把提问定位记进对话 |

每一项都带一个**数字键**（菜单里那个小数字就是它）：按 1~4 直接触发，不必再去够鼠标；
「询问」的输入框**没有长度限制**——从前输入长了它会自己消失（输入框字多到要内部滚动，
那个 scroll 被判成了「视图动了」），现在只认真正的滚动。

**「了解」是一条内置工作流**（与开讲 / 回忆 / 出卷同一套）：词条、出现序号与选中的原文一起交给导师，
它读上下文、写两三句话、调 `api.doc.annotate` 划到正文上——释义因此与这个目标的对话是连贯的，
而不是一段陌生人式的百科。交付物画在用户盯着的那段文字旁边，所以它只响一声铃、**不抢主位**。

**点击学习**：AI 在文中用 `[概念](moji:learn "定位说明")` 布好下一步的学习入口，
已创建与未创建用不同样式区分。

## 复制的是源文

在预览里选中一段按 `Ctrl+C`，进剪贴板的是它在 Markdown 里的原文——公式渲染成的两套 DOM、
注解标记、视觉换行都不跟着走（见 `lib/copySource`）。映射不出来时（整段落在代码块或公式里）
放行浏览器默认那一次：宁可给渲染文字，不能什么都不给。

## 一个节点一份教学文档 + 任意多份笔记

教学文档是超级导师写的讲解正文；笔记是学习者自己那些，**一份笔记一个文件**
（`{节点}.notes/{名字}.md`），可以新建、改名、删除——不同用处的东西各记一份
（「错题本」「摘录」），而不是全堆在一份里。

文档之间用 `[我的笔记](moji:doc/note)` 这样的链接互相跳转，跨节点跳转写成 `moji:doc/#节点id/note`；
**尾巴上还能带行号**：

| 写法 | 打开之后 |
| --- | --- |
| `moji:doc/teaching#L12` | 滚到第 12 行并选中那一行 |
| `moji:doc/teaching#L12-L20` | 选中一段 |
| `moji:doc/teaching#L12@切线斜率` | 选中写的原文 |

讲解里说「你漏的是这一步」时，直接把人送到那一行。沙箱里用 path 指名某一份，
如 `api.doc.append("笔记/错题本", …)`。

## 附件提问

截图或照片直接拖进、或用 `Ctrl+V` 粘进输入框；**任意文件**（源码、csv、日志、pdf 之外的文本类）
从「更多 → 文件」用系统对话框挑，或直接拖进来。附件列在**文字输入区上方**（横向一条，
图片是缩略图、文件是名字 + 体积，都可逐个移除、点击看大图），随消息一起送给模型。

分三条路走：

| 附件 | 怎么走 |
| --- | --- |
| **图片** | 转存进资源库、作为图像片段发出去（**只有当前模型声明了「图像」模态才放行**，不支持的模型会当场说清楚，而不是发出去被服务端拒掉）|
| **文本** | 读成正文拼进这一条消息（上限 6 万字，超出会写明「只附上了开头一部分」），同时存进资源库，导师之后还能用 `res.read` 再读一遍 |
| **二进制** | 读不出文本，只把名字与体积告诉导师 |

## 对话历史与起名

- **一段对话的标题由模型读第一句话起**（`learn/title`，不超过 10 token），起好之后挂在导师栏右上角、
  也列在「更多 → 对话历史」里；还没起好时那里什么都不显示（挂一个「对话 1」等于告诉用户它就叫这个）。
  这个请求刻意做得极窄：**系统提示词 + 那一条消息**，没有工具、没有历史、没有目标上下文——
  起名只需要那一句话，把整段上下文递过去等于为十个字付一整轮的输入钱。它跑在用户那一轮**之外**
  （不阻塞回答），失败就安静地算了、下一轮再试一次；标题只起一次，聊到一半不再改。
  隐藏指令不算「第一句话」（那是我们写给模型的），一条用户消息都还没有时退回**目标问题**。
- **上下文是目标级的**：目标下所有节点共用同一段对话，切节点不换上下文，系统提示词也稳定在目标一级
  （前缀缓存因此不会因为切节点而整段作废）。跨目标切页签时对话栏不会还停在上一个目标。
